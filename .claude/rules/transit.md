# Transit Pipeline

## Pipeline scripts

Numbered 1–8 in `scripts/transit/`; the rebuild script runs them in order.

- `01_download_gtfs.py` — fetches two sources:
  - Official Swiss GTFS feed ("Timetable 2026 (GTFS2020)") from opentransportdata.swiss → `data/gtfs/`. Discovers the latest release at runtime (resource URLs include a date suffix). Refreshed ~2×/week. Carries `original_stop_id` (SLOID) on stops and full sector-range platform codes (e.g. `12A-C`) — required by `gtfs-source-switch` and consumed by `prm-platform-positions`.
  - Atlas v2 traffic-point CSV from opentransportdata.swiss → `data/atlas/actual-date-world-traffic-point.csv`. Per-platform attributes (length, compassDirection) keyed by SLOID; consumed by `prm-platform-positions`.
- `02_download_osm.py` — fetches CH + LI + DE + FR + IT + AT country PBFs → `data/osm/`. Neighbour PBFs are required because the bbox extends past CH soil (Domodossola, Konstanz, Annemasse, Lörrach, Bregenz). One-off download ≈ 12 GB.
- `03_bbox_osm.py` — cuts each country PBF to the bbox in `scripts/transit/config.yaml:osm_bbox`, then merges the slices → `data/osm/ch_pfaedle.osm.pbf`. Cut-then-merge avoids a >10 GB intermediate file. Also produces the way networks for step 07's stop-extent OSM walks (see `stop-extent-osm-walk.md`): `data/osm/rail_ways.geojson` (`railway=rail,light_rail,narrow_gauge`), `data/osm/tram_ways.geojson` (`railway=tram,light_rail,narrow_gauge` — narrow_gauge because tram-classified lines can continue on their own narrow-gauge railway, e.g. the Forchbahn), and `data/osm/street_ways.geojson` (bus-drivable highway classes, with `highway` + `name` kept for the same-street rule). Tram and street extracts are clipped to `streets_stop_buffer_m` buffers around all GTFS stop coords. Extraction runs `osmium tags-filter` + `osmium export` per-country slice (not on the merged PBF — `osmium merge` doesn't fully dedupe cross-border node duplicates and `osmium export` rejects them with "Node ID twice in input"), then Python concats with way-ID dedup and atomic `.tmp` rename. Idempotency is per-artifact — a stale-only extract reruns the per-country cuts + only that extraction, without redoing the slow merge or the other extracts.
- `04_preprocess_gtfs.py` — drops excluded-agency trips, EV-prefixed routes (Bahnersatz / rail replacement), and foreign-terminus trips, repairs `arr > dep` rows, and applies `gtfs_trip_overrides` (see config below) → `data/gtfs_filtered/`.
- `05_run_pfaedle.py` — runs pfaedle in Docker (`carfree-pfaedle:latest`, built from `scripts/transit/pfaedle/Dockerfile`) → `data/gtfs_routed/` with `shapes.txt`.
- `06_score_and_match.py` — loads `data/gtfs_routed/`, runs trip-grouping inside `stream_stop_times`, dedupes per `(line_key, agency_id, trip_group_id, merged_stop_set, direction_key)` so each direction emits its own feature (applies to all buckets including ferry / aerial / funicular mountain since the EXEMPT_DIRECTION_KEY removal — see `remove-exempt-direction-key.md`), then writes `data/transit/transit_lines.geojson` + `line_stops.json`. Also emits `stop_size_scores.json` (per-UIC score + tier for far-zoom dots — see `far-zoom-stop-dot-redesign.md`).
- `07_extract_stops.py` — builds stop dots, pills and connectors → `transit_stops.geojson`, `transit_stop_pills.geojson`. Also loads the step-03 way networks and writes `transit_lines_extended.geojson` — a copy of the step-06 lines with terminal polylines extended: train via the OSM rail walk, tram/bus/regional_bus via the upfront stop-extent fill (sibling borrow → non-sibling borrow → OSM street/tram walk, no straight fallback) — see `stop-extent-osm-walk.md`. Step 06's `transit_lines.geojson` is never modified, so re-running step 07 always starts from pristine line geometry (`--start 7` cannot retain or accumulate stale extensions). Stamps `stop_tier` / `stop_score` from step 06 and runs far-zoom dot dedup (see `far-zoom-stop-dot-redesign.md`).
- `08_build_pmtiles.sh` — tippecanoe → `static/map-assets/tl_*.pmtiles`; the line layer builds from `transit_lines_extended.geojson`, not the step-06 file.

`scripts/generate_style.py` is not numbered — it lives outside `scripts/transit/` because it generates the whole MapLibre style, not transit-only — and runs as a fixed step inside step 7 of the rebuild flow (between extract-stops and pmtiles).

Rebuild: `./scripts/rebuild_transit.sh [--start N] [--force | --force-gtfs | --force-atlas | --force-osm]`. Default is `--start 3` (bbox cut and everything after). Each step's output is the next step's input, so middle-skipping is not supported; `--start N` always runs steps N..8 contiguously. Download steps (1 and 2) skip when the target file is already present; `--force` re-downloads all three (GTFS, atlas, OSM), the per-source `--force-*` flags re-download only that one. This makes `--start 1` cheap to re-run without the multi-GB OSM download.

## Diagnostic outputs (in `data/transit/`)

| File | Contents |
|------|----------|
| `gtfs_filtered.json` | Routes affected by step 04's filter, with `by_agency` / `by_ev_route` / `foreign_terminus` drop counts. |
| `gtfs_unmatched.json` | Trip groups that passed the freq gate but produced no emitted feature (pfaedle never shaped them, or polyline collapsed to <2 coords). One entry per `(line_key, agency_id, trip_group_id)` with `f_weighted` and `freq_score`. |
| `trip_groups.json` | One row per emitted trip group: short_name, long_name, bucket, agency_id, trip_group_id, trip_count, variant_count (per-direction variants since the direction-coverage change). |
| `pfaedle_unrouted.json` | Trips that pfaedle could not shape (rep trip's `shape_id` missing from `shapes.txt`), with `direction_key` recording which direction failed. Aerial GTFS `route_type` 5/6 (cable car / gondola) trips that fail pfaedle do NOT land here — they are emitted with a straight-line fallback instead and tagged `geometry_source: "straight_line_fallback"`. |
| `line_stops.json` | Per emitted feature: ordered list of `[lon, lat, stop_id]` plus the feature's `direction_key`. Stop IDs keep their platform suffix (e.g. `8576646:J`) so per-direction platforms stay distinguishable. |
| `gtfs_groups_full.json` | **Comprehensive lookup.** One entry per `(line_key, agency_id, trip_group_id)` including non-drawable ones, with group-level `drawable`, `raw_freq`, `f_weighted`, `freq_score`, `mountain_origin`, `group_exclusion_reason`, and `freq_gate_window_passed`. Each group lists every `(merged_stop_set, direction_key)` variant including dropped ones, with per-variant `raw_freq`, `f_weighted`, `regional_bus_rescued`, `rare_variant_window_passed`, `kept_by_variant_filter`, `exclusion_reason`, `first_terminus` / `last_terminus`, and (for emitted variants) `feature_id`, `shape_id`, `n_coords`, `line_km`, `rep_trip_id`, `geometry_source`. Read this instead of re-running `stream_stop_times` to debug missing lines. Window/rescue field semantics: see `seasonal-regional-bus-rescue.md`. |
| `stop_attributes_sources.json` | Per-stop atlas attribute lookup, one entry per stop that appears in any drawn line. Each entry carries `status` (`atlas_match` / `no_atlas_match`), the SLOID picked from GTFS `original_stop_id`, and (when matched) `length` (m) and `compass_direction` (degrees). Source for the upcoming pill-alignment work; also surfaces atlas-coverage gaps. |
| `stop_extent_fill.json` | One record per tram/bus/regional_bus line whose backward stop extent needed fill (step 07's upfront fill — see `stop-extent-osm-walk.md`). Carries the driving stop (id, name, coords), `needed_m` (measured against the per-stop fill target: `min(pill-arrow stack need, L)` for buses, fixed L for trams — see the concept § Fill target), `source` (`sibling_borrow` / `nonsibling_borrow` / `walk` / `partial_walk` / `none`), `filled_m`, `deficit_m`. Read by `data/transit/diagnostics/find_pill_offenders.py`, which writes the `pill_offenders.txt` / `pill_shortened.txt` link lists. |

## Pipeline config (`scripts/transit/config.yaml`)

- `osm_bbox` — bbox for the pfaedle PBF.
- `gtfs_stop_overrides` — hand-set `(lon, lat)` per `stop_id`, applied at step 04 (rewrites the matching row + its `Parent…` mirror in `stops.txt`). Last-resort fix for parent stops whose official GTFS coord sits too far from the actual platform for pfaedle to route — the Eiger Express (route 2444) at Grindelwald Terminal is the canonical case: GTFS uses the train-station centroid ~250 m from the V-Bahn boarding gate, outside pfaedle's snap radius for the Eiger Express OSM aerialway, so pfaedle snaps to the closer Männlichenbahn lower station, can't reach Eigergletscher and emits a 2-vertex stub. Coords should come from the matching OSM way endpoint. Affects every trip referencing the stop_id, so verify co-using lines (e.g. Männlichenbahn GGM, Jungfraubahn 65 at the same parents) still snap within radius of their own OSM endpoints from the moved coord. If a co-user breaks, add per-line scoping rather than reverting.
- `gtfs_trip_overrides` — structural rewrites of trips on listed routes, applied at step 04 before pfaedle. Actions: `split_at_stop` (canonical case Niesenbahn, two physical cables joined at Schwandegg) and `insert_waypoint` (forces a shape through a synthetic `WPT:` via-stop that is dropped by everything after routing — canonical case Dornach bus 56's platform-E departure loop). See `gtfs-trip-overrides.md` for matching keys, behavior, and constraints. Audit output: `data/transit/gtfs_trip_splits.json`.
- `excluded_agencies` — token list, case-insensitive substring match on `agency_name`. Drops the agencies' trips entirely at step 04. Used to suppress long-distance coaches (Flixbus, BlaBlaCar, etc.).
- **EV-prefix route drop** (hardcoded in step 04, no config key): any route whose `route_short_name` begins with `EV` (case-insensitive) is excluded before pfaedle runs. Targets Bahnersatz / rail-replacement services (SBB-EV, BLS-EV, FART-EV, TPC-EV, plus EV-numbered lines from non-EV agencies). The MVP map shows general year-round connections; replacement services belong to a future daily-updating variant.
- `mountain_agency_ids` — exact GTFS `agency_id` whitelist. Each listed agency's rail trips are rebucketed to `mountain` at `load_trips` time. This drives the yellow rendering style (light yellow color, fixed width). It does **not** exempt the trips from the freq-score or active-days gates — those exemptions are restricted to aerial / funicular per the direction-coverage concept. Rebucketed trips carry `mountain_origin: "rebucketed_rail"` on every emitted feature. Criterion: "agency is outside the GA-Geltungsbereich"; Rigi Bahnen is a manual exception. Always agency_id, never name substrings — the substring approach previously matched both BOB main (valley) and BOB-spb (Schynige Platte) and broke the Interlaken–Lauterbrunnen line.
- `freq_sampling.weekday_dates` / `freq_sampling.weekend_dates` — explicit sample dates the low-frequency filter measures against. The generator that produced them is documented in `multi-date-frequency-sampling.md`; rules + seed live in that generator (deleted after first run; re-create it from the concept doc when the feed period changes).
- `frequency.best_freq` / `frequency.worst_freq` — per-mode trips/hour endpoints of the score curve. `f_weighted >= best_freq` → score 1.0; `f_weighted <= worst_freq` → score 0.0 (and the line drops; aerial/funicular mountain is gate-exempt; ferry treatment per `pill-rendering.md` § "Ferry stops"). Every bucket appearing in either table must appear in both. See `frequency-weighted-line-scoring.md`.
- `window_weights` — `core` / `eve` / `we` weights (must sum to 1.0) applied to the per-window trips/hour to produce `f_weighted`. Currently 0.6 / 0.2 / 0.2.
- `min_active_days_regional_bus`, `unique_stop_min_distance_m`, `unique_stop_min_share_pct` — seasonal regional-bus rescue knobs. See `seasonal-regional-bus-rescue.md`.
- `line_width` — per-mode `min` / `max` width_base endpoints. Score 0 maps to `min`, score 1 to `max`. Mountain carries a deliberately narrow `min`/`max` spread (currently 1.5 / 2.5) so frequency varies the line slightly, but the mode's visual identity stays close to fixed. `freq_score` is computed per emitted variant (per direction), not per group; see `seasonal-regional-bus-rescue.md` § "Per-variant freq for line thickness".
- `pill_rendering.osm_match_radius_m` / `osm_match_max_tangent_diff_deg` / `osm_fallback_max_straight_m` — tune the rail missing-range fill at train terminals. See `stop-extent-osm-walk.md` § "Rail walk".
- `pill_rendering.road_match_radius_m` / `road_match_max_tangent_diff_deg` — gates of the tram/bus stop-extent walk (the final fill tier after both borrows; no straight fallback). See `stop-extent-osm-walk.md` § "Walk tier for tram / bus / regional_bus".
- `streets_stop_buffer_m` — buffer radius around GTFS stop coords to which step 03 clips the tram / street way extracts.
- `pill_design_bands.{A,B,C}` — per-zoom-band pill construction constants (thresholds, radii, sizing). See `pill-rendering.md`.
- `pfaedle.image` / `pfaedle.modes` — image tag and routed modes.
- `pfaedle.station_move_penalty_fac` — seconds-per-metre cost of moving a stop's matched edge away from its GTFS coord. Overrides pfaedle's built-in default (0.0039) via `-P`. Currently `0.05`. Boosting it makes pfaedle prefer closer-to-the-platform snaps even when that costs extra route distance. The canonical case it fixes is a terminal stop on a oneway curb (Bern Bahnhof platform H on BernMobil bus 21 outbound): pfaedle's default would snap the trip's first node onto the bidirectional main road ~22 m east of the platform rather than route the legal ~50 m loop south down the bus-only sideroad and back up Bahnhofplatz. The override **must** be scoped to a mode section (`[bus]`) — `-P` accepts unscoped overrides syntactically but silently never applies them during routing. Currently only the `[bus]` section is overridden; if a tram/rail terminal exhibits the same symptom, add the section there too.

## Identity model

`stream_stop_times` partitions trips by `(long_name_norm or short_name, agency_id, bucket)`, runs union-find on merged stop sets within each partition (≥2 shared merged stops → same group), and assigns a `trip_group_id` unique within its partition. **`trip_group_id` is unique only within a partition**, so the emission key in `main()` is `(line_key, agency_id, trip_group_id, merged_stop_set, direction_key)` — the per-direction split makes opposite directions of the same merged_stop_set distinct features. Forgetting `agency_id` here causes same-numbered lines in different cities to collide (e.g. BernMobil bus 10 vs Stadtbus Winterthur bus 10); forgetting `direction_key` causes one-way visuals for trams whose two directions use different OSM ways (Bern Tram 3, 7, 8 around Bahnhof).

`direction_key` is `(first_merged_uic, last_merged_uic)` from the trip's stop sequence. GTFS `direction_id` is not used — it is empty for many Swiss feeds, including all BernMobil trams. Loop trips (first == last UIC) all share one direction_key and emit a single feature. No bucket is exempt from the per-direction split — ferry / aerial / funicular were previously collapsed via the EXEMPT_DIRECTION_KEY sentinel; that exemption was removed (see `remove-exempt-direction-key.md`) and they now split per direction like every other bucket.

`_trip_group_export` (`trip_id → (line_key, tg_id, agency_id)`), `_trip_stops_export` (`trip_id → [stop_id, ...]`), `_trip_merged_export` (`trip_id → frozenset(merged stop ids)`), `_trip_weight_export` (`trip_id → sample-day activity count`), and `_trip_direction_export` (`trip_id → (first_uic, last_uic)`) expose the per-trip info the emission loop needs. They are populated as side effects of `stream_stop_times` and read by `main()`. They are the only export surface; there is no separate `_line_canonical_export` or `CanonEntry` table — the legacy short/long-name dual-index that used to live alongside them was removed once the pre-pfaedle OSM matcher (which was its only consumer) went away.

## Close-zoom pill-arrows (z17+)

**Terminology:** the close-zoom stop labels — the elongated polygons with the line drawn through them — are called **pill-arrows**. This is the canonical, established name (used throughout `close-zoom-stop-design.md`). Always use it; do not substitute "pill", "arrow", "stop label", or other ad-hoc terms.

Settled architecture: STRAIGHT metre-fixed polygons baked into the tiles, queued along the stop position line (the fitted extent re-used from the stop/dot placement — the arrival line's at terminals) extended dead straight beyond its range; per-pill axis from the average direction (chord) of the course part the pill spans. Curved bodies, sprite/symbol pills (pixel-fixed), and line-rendered bodies were each fully implemented and reverted — do not retry them; the reasons and renderer limitations are recorded in `close-zoom-stop-design.md`. Build-time text measuring uses `scripts/transit/glyph_widths.json` (regenerate with `gen_glyph_widths.py` when the font stack changes).

## Service area filter

`is_in_service_area(stop_id)` filters by UIC prefix 85 (Swiss + Liechtenstein) with hardcoded `_SERVICE_AREA_EXCLUDE` / `_SERVICE_AREA_INCLUDE` overrides at the border. Kept in 05 but no longer called by the active main pipeline; available for stop-side filters if needed later.

## Mountain and ferry

Every variant goes through pfaedle, including mountain (extended route_types 1300 / 1303 / 1400 / 116) and ferry (extended route_type 1000). When pfaedle produces a shape, it is used; mountain features keep their fixed light-yellow color (frequency varies width only slightly per the deliberately narrow `line_width.mountain` spread). Straight-line fallback is reserved for aerial extended `route_type` 1300 (aerial lift) and 1303 (elevator-style, e.g. Bern Aufzug) — these emit a straight line between consecutive stops when pfaedle has no shape, tagged `geometry_source: "straight_line_fallback"`. Funiculars (1400), rack & pinion (116), ferries, and every other mode that pfaedle fails to shape are dropped and logged to `pfaedle_unrouted.json`, same as rail/bus.

Mountain classification comes from extended `route_type` ∈ {1300, 1303, 1400, 116} plus the `mountain_agency_ids` whitelist (rebuckets listed agencies' rail extended-100s trips to `mountain` at `load_trips`). Rack railways outside that whitelist still land in `mountain` via their native 116 code. Every mountain feature carries `mountain_origin` ∈ {`aerial` (1300, 1303), `funicular` (1400), `rack` (116), `rebucketed_rail` (100s via whitelist)}.

**Exemptions** are scoped by `mountain_origin`, not the bucket alone, and cover two gate rules: freq-score gate (`f_weighted > worst_freq`) and active-days gate (`min_active_days`). `aerial`, `funicular`, and `ferry` are exempt from both gates. The per-direction split applies to every bucket including these three — see `remove-exempt-direction-key.md`. `rack` and `rebucketed_rail` are treated like normal `train`: both gates apply. The rare-group filter still treats the full mountain bucket as exempt. The active-days gate threshold is per-bucket via `min_active_days_by_bucket` in `scripts/transit/config.yaml` — currently `mountain: 90` so summer-only rack railways (Schynige Platte, Brienzer Rothorn) still draw; everything else falls back to the `min_active_days` default of 150.

`deduplicate_mountain()` collapses overlapping features per `ref` (no direction_key in the key) and only for `mountain_origin == "aerial"`. Best vertex count wins the bbox-overlap tiebreak. Opposite directions of an aerial cable share a bbox and so get collapsed into one feature by this same mechanism. Funiculars, rack, rebucketed rail, and other modes are not collapsed because a shared bbox typically indicates two different branches off a common stem rather than a duplicate.

## Route type classification (extended GTFS codes)

The official OTD feed uses extended GTFS `route_type` codes (3–4 digit). See `gtfs-source-switch.md` for the full rationale. Summary of the mapping in `06_score_and_match.py:gtfs_type_to_bucket`:

- **train**: 100, 101, 102, 103, 105, 106, 107 (Tourist Railway — rebucketed to mountain via `mountain_agency_ids` when applicable), 109
- **mountain**: 116 (rack), 1300 (aerial lift), 1303 (Bern Aufzug-style elevator), 1400 (funicular)
- **metro**: 401
- **bus**: 700, 702 (the bus-mode-classification concept decides city_bus vs regional_bus); 800 (trolleybus, fixed city_bus, bypasses the regional reclassification)
- **tram**: 900
- **ferry**: 1000
- **excluded** (not drawn): 117 (EXT — extra/event trains), 202 (National Coach), 705 (BN — night buses), 710 (Sightseeing Bus), 715 (Demand & Response Bus), 1500 (Taxi), and any unknown extended code

**715 Demand & Response Bus** exists in the feed (~78 PostAuto routes — PubliCar etc.) but has no fixed timetable that this map can render. Future work could draw on-demand services as a distinct mode if useful.
